## Release 86 (Mar 2023)
### New Data Export API
Version 2 of the Data Export API has been released that supports Partner > Client execution.

The following Version 1 APIs have been deprecated
- `v1/exports [GET]`
- `v1/export/{data_export_id} [GET]`
- `v1/export/status/{job_id} [GET]`

### Profile API Deprecated
Version 2 of lookup API has been enhanced to cover all Profiles previously supported by the dedicated Profile API. The Lookup APIs provide a standard way to retrieve reference data, and support additional types.

The following Version 1 APIs have been deprecated
- `v1/company/profiles [GET]`

## Release 83 (Sept 2022)
### OAuth Support
Support for OAuth Authorization Code Flow with PKCE and Client Credential Flow has been added.
- `v2/companies/<company_id>/oauth2/authorize`
- `v2/companies/<company_id>/oauth2/token`

These APIs leverage OAuth Applications that must be configured in the application prior to use. Refer to <a onclick="loadResourcePartial(event, 'Foundations.html', 'Foundations')"> Foundations </a> & <a onclick="loadResourcePartial(event, 'Client id and secret.html', 'Client id and secret')"> Client id and secret </a> for more information.

**Note:** The OAuth APIs will replace the previous `v1/login` that leverage a form of OAuth Resource Owner Password Credential (ROPC). Deprecation information on the `v1/login` API will be published at a future date in accordance with the Deprecation Policy.

## Release 55 (Feb 2018)
### V1 Time-Entry & Cost Center APIs removed

The HTTP POST, PUT and DELETE method for the `/v1/employee/time-entry` APIs have been removed. Any calls to these API will now return an HTTP 405 response.
Any consumer of the API not already updated should immediately switch to the V2 versions to avoid interruption.

## Release 47 (Oct 2016)
### Version 2 Released
Version 2 of the REST API has been released that improves usability and performance. V1 resources will continue to function in accordance with the Deprecation & Versioning policy

### V1 Login (HTTP GET) Removed
The HTTP GET method for the `/v1/login` API has been removed. Any calls to this API will now return an HTTP 405 response.
Any consumer of the API not already updated should immediately switch to the HTTP POST version of the API to avoid interruption.
