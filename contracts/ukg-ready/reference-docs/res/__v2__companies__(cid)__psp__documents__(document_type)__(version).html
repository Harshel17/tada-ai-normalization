Document Version

POST

Submits a Payment Service Platform document for processing and storage. **General Behavior:** - Validates the request body according to the document type and version - Checks document size against company's maximum file size setting - Creates a document upload record linked to the company - Stores the document in blob storage - Returns the document upload name and ID upon successful storage **Security Requirements:** The authentication token must have the required security access: - "Modules > REST API Resources > PSP Documents > Add checkbox" - "Distribution > Distribution > Upload Service Provider Documents checkbox" - Requires "Integrated Document Storage" Marketplace Product **Document Access:** - Uploaded documents will be visible in "Distribution > Tools > Upload Service Provider Documents" **Supported Document Types:** | Document Type | Version | Description | Request Body Schema | Request Body Example | |--------------|---------|-------------|-------------------|---------------| | `direct-deposit-reject` | v5 | Rejected/returned Direct Deposit transactions | [psp-direct-deposit-reject-request-v5-schema.json](../raml/public/endpoints/psp/schema/psp-direct-deposit-reject-request-v5-schema.json) | [psp-direct-deposit-reject-request-v5-example.json](../raml/public/endpoints/psp/examples/psp-direct-deposit-reject-request-v5-example.json) | **Note:** For detailed schemas, validation rules, and examples for each document type, refer to the document-type-specific RAML files in the same directory.

Parameters

Path Parameters
  • cid
    string
    required

    Example: 123456

    Company should be referenced via company id or company unique id or company short name using `|short_name` or `!short_name` format.
  • document_type
    string
    required

    Example: direct-deposit-reject

    The type of PSP document to submit.
  • version
    string
    required

    Example: v5

    The version of the document schema.

Responses

Document has been accepted and stored successfully. Returns the document upload ID.

Bad request. Possible reasons: - Missing required fields - Invalid field values - File size exceeds company's maximum document size - Unsupported document type - Unsupported version - Document type not configured for the company

Forbidden. User lacks required security permissions.

Internal server error. Document upload creation or blob storage failed.
