Authentication

These APIs are intended to allow authentication of users via a 3rd Party OAuth 2 Authentication server such as Okta, OpenAM etc. ClientId and Secrets must be configured within the applications OAuth Configuration screen prior to use. These APIs are intended for interactive login through the Applications user interface and cannot be used to authenticate the applications data APIs. For API Authentication see <a href="/ta/docs/rest/public/?r=__v1__login#post">Login</a> or <a href="/ta/docs/rest/public/?r=__v2__companies__(cid)__oauth2__authorize#get">Authorize</a>.

GET

Endpoint for initiating Authorization Code Flow by OAuth client.

Parameters

Path Parameters
  • cid
    string
    required

    Example: 123456

    Company should be referenced via company id or company unique id or company short name using `|short_name` or `!short_name` format.
Query Parameters
  • client_id
    string
    required

    Example: 0e4432b3-8f3b-486d-8bc0-72518acd8d79

    Client Id from OAuth Configuration.
  • state
    string

    Example: state=key1=value1&key2=value2

    State parameter used to redirect users to specific screen after login. <br>Supported keys: <ul> <li>`target_id` - external id of .home page, the recommended way to navigate to a specific page.</li> <li>`target_url` - native url of a page, it can be changed without any notifications in upcoming releases.</li> </ul> <b>Note:</b> `=`, `&` characters in value of the query parameter should be url encoded.

Responses

The request is valid and the user redirected to OAuth Authorization Code Flow.

Returned in case the company is locked or available functionality is disabled.

Returned in case invalid Company or OAuth Configuration references are provided.
