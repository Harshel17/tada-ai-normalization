Document Storage

Integrated Document Storage (IDS) allows a company to store documents directly within the application. This feature offers a useful, centralized way to keep and distribute data pertaining to key processes like Human Resources management, Payroll, or Time and Labor Management.

GET

Retrieves a list of uploaded documents. Each object represents the metadata of a single uploaded file. There are two types of documents: global documents and attached documents. - An attached document has a reference to a specific resource in the system, such as a timesheet document. - A global document is uploaded by a system administrator and does not have a reference but can be browsed by users in a common place (e.g., Tax Documents, Company Documents). Each returned document contains links to its content with a short expiration time. The response may contain one of the following links: - `content_r` - provides read-only access - `content_rw` - provides read-write access - `content_w` - provides write-only access Refer to the [File Upload/Download](#File_Upload_Download) section for information about the file content upload process. This functionality is available for companies with the "Integrated Document Storage" marketplace product.

Query Parameters
  • type
    string
    required

    Valid values: COMPANY_DOCUMENT, TIMESHEET_DOCUMENT, TIME_OFF_DOCUMENT_V2, HR_EMPLOYEE_DOCUMENT, HR_APPLICANT_RESUME, BENEFIT_REQUEST_DOCUMENT, ACCOUNT_DIRECT_DEPOSIT, HR_ACTION_REQUEST_DOC_UPLOAD, HR_ACCOUNT_CHECK_LIST, HR_CHECK_LIST_ITEM, CUSTOM_FORM, DISCIPLINE_INCIDENT, TAX_DOCUMENT, LEAVE_OF_ABSENCE_CASE, LEAVE_OF_ABSENCE_REQUEST

    Type of uploaded documents.
  • linked_id
    integer
    ID of object that is linked to requested documents. Omitting this parameter returns all documents of that type for the specified company. It is applicable to the following "type"s: "TIMESHEET_DOCUMENT", "TIME_OFF_DOCUMENT_V2", "HR_EMPLOYEE_DOCUMENT", "HR_APPLICANT_RESUME", "BENEFIT_REQUEST_DOCUMENT", "ACCOUNT_DIRECT_DEPOSIT", "HR_ACTION_REQUEST_DOC_UPLOAD", "HR_ACCOUNT_CHECK_LIST", "HR_CHECK_LIST_ITEM", "CUSTOM_FORM", "DISCIPLINE_INCIDENT", "LEAVE_OF_ABSENCE_CASE", "LEAVE_OF_ABSENCE_REQUEST"
  • sort_by_created_at
    string

    Valid values: ASC, DESC

    For sorting documents by created at date.
  • modified_from
    date-only

    Example: 2016-03-14

    Used for getting documents which have been created or modified from date lower bounded. Should be in `yyyy-mm-dd` format. If modified_to is supplied, modified_from is required.
  • modified_to
    date-only

    Example: 2016-10-31

    Used for getting documents which have been created or modified to date upper bounded. Should be in `yyyy-mm-dd` format. Maximum difference between `from` and `to` dates can be 60 days. If modified_to is supplied, modified_from is required.

POST

Initiates the document upload process, which consists of three steps: 1. Create metadata that describes the file. 2. Get a link to the file content. 3. Upload the file's content. This operation covers metadata creation only. After metadata is created, it provides a link to the document resource, where a link to the file content can be obtained. This functionality is available for companies with the "Integrated Document Storage" marketplace product. The file name or extension must not contain the characters: ", *, :, <, >, ?, \\, /, | **Specific attributes for types of documents** It is possible to specify additional attributes for certain documents.
