Authorize

<br>These APIs are intended for authorizing requests to the application apis using OAuth 2.0 Authentication Code Flow with PKCE or Client Credential Flow. ClientId and Secrets must be configured within the applications Company Setup screen prior to use. These APIs cannot be used to authenticate login to the user interface. <br>For authentication of user login using a 3rd party Authentication Server see <a href="/ta/docs/rest/public/?r=__v2__companies__(cid)__session__oauth__auth#get">link</a>.

GET

The authorization endpoint is used to interact with the resource owner and obtain an authorization grant. Implements The OAuth 2.0 Authorization Framework Authorization Endpoint <a href="https://www.rfc-editor.org/rfc/rfc6749#section-3.1" target="_blank"> rfc6749 section-3.1 <i class="fa fa-external-link" aria-hidden="true"></i></a> . Is used by the authorization code grant type to fulfill Authorization Request <a href="https://www.rfc-editor.org/rfc/rfc6749#section-3.1" target="_blank">rfc6749 section-4.1.1 <i class="fa fa-external-link" aria-hidden="true"></i></a>. This implementation of the OAuth Authorization code flow requires the use of <a href="https://www.rfc-editor.org/rfc/rfc7636" target="_blank">Proof Key for Code Exchange (PKCE) <i class="fa fa-external-link" aria-hidden="true"></i></a>. As such certain parameters which are optional in the basic specification for Authorization code flow are mandatory and must be provided by the calling client. The additional required parameters are shown as such in list of parameters below.

Parameters

Path Parameters
  • cid
    string
    required

    Example: 123456

    Company should be referenced via company id or company unique id or company short name using `|short_name` or `!short_name` format.
Query Parameters
  • response_type
    string
    required

    Example: code

    Value MUST be set to "code". See response_type description <a href="https://www.rfc-editor.org/rfc/rfc6749#section-4.1.1" target="_blank">rfc6749 section-4.1.1 <i class="fa fa-external-link" aria-hidden="true"></i></a>
  • client_id
    string
    required

    Example: 1eca38b7-0b27-49e2-a7da-b5f44123c38e

    Valid interactive oauth application id. See client_id description <a href="https://www.rfc-editor.org/rfc/rfc6749#section-4.1.1" target="_blank">rfc6749 section-4.1.1 <i class="fa fa-external-link" aria-hidden="true"></i></a>
  • redirect_uri
    string
    required

    Example: https://www.public-client-app.com/oauth2/callback

    The uri the authorization server directs the resource owner's user-agent after completing its interaction with the resource owner. See redirect_uri description <a href="https://www.rfc-editor.org/rfc/rfc6749#section-4.1.1" target="_blank">rfc6749 section-4.1.1 <i class="fa fa-external-link" aria-hidden="true"></i></a>
  • code_challenge
    string
    required

    Example: P3nj-_3SAHMtSss75ulTzhLMQtMcOGQpm0e0KfJDW8Q&

    A challenge derived from the code verifier that is sent in the authorization request, to be verified against later. See <a href="https://www.rfc-editor.org/rfc/rfc7636" target="_blank">rfc7636 <i class="fa fa-external-link" aria-hidden="true"></i></a> for details.
  • code_challenge_method
    string
    required

    Example: S256

    Value MUST be set to "S256". A method that was used to derive code challenge. See <a href="https://www.rfc-editor.org/rfc/rfc7636" target="_blank"> rfc7636 <i class="fa fa-external-link" aria-hidden="true"></i></a> for details.
  • state
    string

    Example: https://www.public-client-app.com/oauth2/callback

    An opaque value used by the client to maintain state between the request and callback. The authorization server includes this value when redirecting the user-agent back to the client. The parameter SHOULD be used for preventing cross-site request forgery. See state description <a href="https://www.rfc-editor.org/rfc/rfc6749#section-4.1.1" target="_blank">rfc6749# section-4.1.1 <i class="fa fa-external-link" aria-hidden="true"></i></a>

Responses

The request is valid and the user redirected to Authentication. The Location response header indicates the Authentication URL to redirect a page to.
