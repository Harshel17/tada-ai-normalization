HTTP Headers

The API supports a variety of HTTP headers.

---
The API supports the following HTTP headers.

# Supported HTTP headers
## Key

* {header name} (Request/Response)
    * {comment}

## Headers

* Accept (Request)
    * By default, do not pass this header; text/csv can be passed only in supported API operations
* Authorization (Request)
    * Authentication and authorization data
* Authentication
    * Legacy Authentication header used by `/v1/login`
* RequestId (Response)
    * ID for tracking requests
* Content-Type (Request)
    * application/json, application/xml or text/csv (for supported API operations)
* Location (Response)
    * URI representing the current status of an asynchronous request
* X-CallLimit-Threshold (Response)
    * Current API throttling threshold for the company
* X-CallLimit-CurrentCalls (Response)
    * Number of API calls within the throttling window. This is the total of all calls not just the current user
* X-CallLimit-TimeToWait (Response)
    *  Milliseconds until next API call will be allowed once throttling threshold is reached
* Deprecated (Response)
    * Information about deprecation status of an API
* X-End-of-Support-Timeline (Response)
  * Information about when support for an API will be dropped
* X-Removal-Timeline (Response)
  * Information about when an API will be removed

# Standard HTTP headers
Almost every API call requires the following standard headers:

* content-type : application/json
* Authorization : ACCESS_TOKEN Note: Replace ACCESS_TOKEN with the token generated during the Generate a token exercise.
